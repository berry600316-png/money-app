# 用 iPhone 捷徑收集刷卡通知（功能 A 設定說明）

> **2026-10-13 起（D-128）：Money 只會自動辨識「LINE 錢包」的 LINE Pay 付款完成通知**（設定見下方「二之二」）。
> 其他 App 的通知（包括 Richart Life 刷卡通知）匯入時會列在「不匯入」並寫出原因，請自己記帳；等拿到該 App 的真實通知原文、建立專用格式後才會自動辨識。

> **狀態：未經實機驗證。** 本說明依 iOS 捷徑一般的操作方式撰寫。你在 2026-10-11 確認過 iOS 27 的捷徑有「App 通知」觸發器、可以選 Richart Life；
> 但觸發器實際的中文名稱、能拿到哪些通知欄位、能否鎖定時執行，都還沒實測。下面標 ⚠️ 的地方請以手機上實際看到的為準，並把結果告訴我。

## 整體流程

刷卡 → Richart Life 跳出通知 → 捷徑自動化被觸發 → 把通知內容存成一個 JSON 檔到「我的 iPhone › MoneyApp › Inbox」 →
之後打開 Money →「明細 › 匯入刷卡紀錄」→ 選取這些檔案 → 預覽 → 匯入。

刷卡當下不需要打開 Money。重複選到已匯入的檔案也不會重複記帳（用 captureId 判斷）。

## 一、建立資料夾（只做一次）

1. 打開「檔案」App →「瀏覽」→「我的 iPhone」。
2. 長按空白處 →「新增檔案夾」→ 命名 `MoneyApp`。
3. 進入 `MoneyApp`，再新增一個檔案夾 `Inbox`。

請選「我的 iPhone」，不要選 iCloud Drive：iCloud 會把檔案同步到雲端，不符合「資料只在這支 iPhone」的原則。

## 二、建立自動化

1. 打開「捷徑」App → 下方「自動化」→ 右上角「＋」。
2. 在觸發器清單選 ⚠️「App 通知」（或類似名稱）→ App 選 **Richart Life**。
   若有「通知內容包含…」之類的篩選，先**不要**設定，讓所有 Richart Life 通知都進來（Money 會自己判斷哪些是刷卡）。
3. 選 **「立即執行」**，並關閉 **「執行時通知」**。⚠️ 若沒有「立即執行」選項，代表 iOS 要求你每次確認，請回報。
4. 按「下一步」→「新增空白自動化」，依序加入下列動作：

### 動作 1：「格式化日期」— 產生擷取時間
- 日期：**目前日期**
- 日期格式：**ISO 8601**，包含時間
- 把結果重新命名為 `擷取時間`（點結果 → 重新命名）

### 動作 2：「隨機數字」— 產生唯一編號的一部分
- 最小值 `100000`、最大值 `999999`

### 動作 3：「文字」— 組出 captureId
- 內容：`擷取時間` 變數 + `-` + `隨機數字` 變數
- 重新命名為 `captureId`

### 動作 4：「字典」— 組出通知 JSON
依下表新增鍵值（類型照表格選）：

| 鍵 | 類型 | 值 |
|---|---|---|
| `schemaVersion` | 數字 | `1` |
| `captureId` | 文字 | 變數 `captureId` |
| `sourceApp` | 文字 | `Richart Life` |
| `sourceType` | 文字 | `notification` |
| `title` | 文字 | 變數「捷徑輸入」→ ⚠️ 選代表**標題**的屬性 |
| `subtitle` | 文字 | 變數「捷徑輸入」→ ⚠️ 選代表**副標題**的屬性（沒有就留空） |
| `body` | 文字 | 變數「捷徑輸入」→ ⚠️ 選代表**內文**的屬性 |
| `notificationTime` | 文字 | 變數「捷徑輸入」→ ⚠️ 選代表**通知時間**的屬性（沒有就用 `擷取時間`） |
| `capturedAt` | 文字 | 變數 `擷取時間` |

> ⚠️ 如果「捷徑輸入」點開後只有一個整段文字、沒有標題／內文之分，就把它整段放進 `body`，`title`、`subtitle` 留空。Money 會從整段文字找金額、商店與時間。

### 動作 5：「取得字典的文字」或「文字」— 轉成 JSON 文字
- 加入「文字」動作，內容只放「字典」變數。（字典轉成文字就是 JSON 格式。）

### 動作 6：「設定名稱」
- 名稱：`money-` + 變數 `captureId` + `.json`

### 動作 7：「儲存檔案」
- 關閉 **「詢問儲存位置」**
- 目的地：**我的 iPhone › MoneyApp › Inbox**
- 關閉 **「覆寫已有檔案」**（每則通知各存一個檔，不覆蓋舊檔）

5. 按「完成」。

## 二之一、其他銀行的 App（多張卡）

每一個收刷卡通知的銀行 App 各建一個自動化，步驟和上面完全相同，只有兩處不同：

1. 觸發器的 App 改選那家銀行的 App。
2. 動作 4 字典裡的 `sourceApp` 改成那個 App 的名稱，例如 `CUBE`、`中信 Home Bank`。**同一個 App 每次都要寫得一模一樣**：Money 用這個名稱決定要用哪家銀行的解析格式，也用它記住「這個 App 的通知沒有卡號時記到哪張卡」。

所有銀行的檔案都可以存進同一個 `Inbox` 資料夾，匯入時一次選取即可；Money 會依 `sourceApp` 分開處理。

> 在你提供各銀行的真實通知原文、並建立該銀行的解析格式之前（見 `docs/adding-a-bank.md`），該銀行的通知都會列在「不匯入」（D-128：不再用通用規則猜金額與商店）。

## 二之二、LINE Pay（LINE 錢包通知）

LINE Pay 的付款通知由 **LINE** App 發出，通知標題是「LINE錢包」。建立方式和上面相同，差別：

1. 觸發器的 App 選 **LINE**。⚠️ LINE 的聊天訊息也是 LINE App 的通知；若觸發器能設定「標題包含 LINE錢包」之類的條件，請設定，減少存下私人聊天的檔案。不能設定也沒關係：Money 只會認「標題是 LINE錢包」而且內文是「LINE Pay 付款 NT$… 付款完成。商店名稱：…」的通知，聊天訊息一律不匯入，也不會保存它的內文（D-131）。
2. 動作 4 字典裡的 `sourceApp` 填 **`LINE`**（不是 `Richart Life`）。
3. `title` 一定要放通知的**標題**（應該是「LINE錢包」），`body` 放內文。⚠️ 如果捷徑拿不到分開的標題，只有整段文字，Money 會認不出來（因為要靠標題分辨是 LINE 錢包還是朋友的聊天），請回報 V2。
4. 每則通知各存一個檔，`captureId` 每則都要不同（動作 1～3 的「擷取時間＋隨機數字」就是為了這個）。如果同一個編號出現兩則不同內容，Money 會列為「不匯入」並提示檢查捷徑。

匯入時，LINE Pay 的消費會記到「設定 › 帳戶與付款方式 › LINE Pay」裡「付款通知記到哪張卡」的那張（LINE Pay 只綁一張卡時就是它，D-133）；預覽時可以逐筆改成別張信用卡或金融卡。通知本身不會寫是哪張卡，所以一種通知固定對應一張卡。

## 三、測試

1. **先手動測一次**：在自動化的編輯畫面按右下角「▶︎」執行。因為沒有真的通知，欄位會是空的，但應該會在 Inbox 看到一個 `money-…json` 檔。
   → 打開 Money「明細 › 匯入刷卡紀錄」選它，會顯示「沒有通知內容」，這是正常的。
2. **真的付一筆小額消費**（例如用 LINE Pay 在便利商店付款）。等通知跳出後：
   - 打開「檔案 › 我的 iPhone › MoneyApp › Inbox」，應該多一個 JSON 檔。
   - 在 Money 匯入它，預覽應顯示正確的商店、金額、時間。
3. **鎖定狀態**：手機鎖定時刷一筆，解鎖後看 Inbox 有沒有新檔案。

## 附錄：JSON 格式（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "captureId": "2026-10-11T14:05:12+08:00-483920",
  "sourceApp": "Richart Life",
  "sourceType": "notification",
  "title": "刷卡通知",
  "subtitle": null,
  "body": "（Richart Life 通知原文）",
  "notificationTime": "2026-10-11T14:05:10+08:00",
  "capturedAt": "2026-10-11T14:05:12+08:00"
}
```

- 每個欄位都可以是空的（`null` 或 `""`）；`title`、`subtitle`、`body` 至少要有一個。
- 一個檔案可以放一則，也可以放一個陣列（多則）。
- 沒有 `captureId` 時，Money 會用內容算出一個編號，同樣的通知一樣不會重複匯入。
- 時間可以是 ISO 8601，也接受「2026年10月11日 下午2:05」這類捷徑常見的寫法。
- 範例檔（模擬資料，不是真實通知）：`docs/samples/notifications/`。
- 一個檔案最大 1 MB；一次最多讀 300 則通知，其餘下次再匯入（D-131）。
- LINE Pay 範例（`sourceApp` 為 `LINE`、`title` 為 `LINE錢包`）：

```json
{
  "schemaVersion": 1,
  "captureId": "2026-10-13T10:30:00+08:00-583924",
  "sourceApp": "LINE",
  "sourceType": "notification",
  "title": "LINE錢包",
  "subtitle": null,
  "body": "LINE Pay 付款 NT$ 120 付款完成。商店名稱：範例商店：回饋：……",
  "notificationTime": "2026-10-13T10:30:00+08:00",
  "capturedAt": "2026-10-13T10:30:00+08:00"
}
```

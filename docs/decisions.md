| D-83 | 去重：同 captureId＝重複（略過，含已刪除的那筆）；同卡、同金額且通知時間 ±10 分鐘，或同日同金額且商店相近＝疑似重複（預設不匯入，使用者可勾選匯入）。同批次內也互相比對。 |

| D-86 | PDF 用 PDF.js（pdfjs-dist 5.7.284）在 iPhone 本機解析；worker 與 CJK cMap 隨 PWA 打包並預快取。密碼只存在記憶體、只用一次。掃描影像（無文字）明確告知不支援。 |
| D-87 | 帳單解析分兩層：PDF→文字行（通用）與「銀行格式轉接器」。目前只有通用轉接器（偵測日期＋金額行），沒有真實台新樣本前一律標「帳單解析待確認」，使用者在預覽可修改、刪除、補登明細，確認後才可標為已確認。 |

| D-89 | 核對引擎獨立於 UI（`src/card/reconcile.ts`），規則集中在 `RECONCILE_RULES`：同卡、金額相同、日期差 ≤3 天（只有入帳日時 ≤7 天）才是候選；唯一候選且（商店相近或日期差 ≤1 天）→ 自動核對；多個候選且無法以商店唯一區分 → 需要確認；同卡、日期 ≤3 天、商店相近但金額差 ≤10% → 需要確認（金額不一致）。 |
| D-90 | 一筆帳單明細最多對一筆記帳，一筆記帳最多被一筆明細使用（跨所有帳單）。退款、手續費、分期、調整、其他非一般消費的明細一律「需要確認」，不自動核對；繳款不參與核對，列在帳單其他資訊。 |
| D-91 | 記帳多的範圍：同卡、消費日期落在帳單週期內的支出。帳單週期未確認時不判定記帳多（只提示）。週期最後 5 天內的未配對記帳視為「可能下期列帳」，不算記帳多。使用者可標「等待下期帳單」。 |
| D-92 | 核對關係保存配對當下的金額／日期／卡片；記帳之後被修改或刪除，關係自動變成「需要確認（記帳已變更）」，不會顯示為已核對。核對永遠不修改記帳的消費日期；只有使用者按「改成帳單金額」才改金額。 |
| D-93 | 「已核對」標示只出現在已核對的信用卡交易旁；未核對不加任何警示（沒有帳單≠有問題）。 |
| D-94 | 信用卡資料（通知紀錄、匯入批次、帳單、明細、核對關係）納入 JSON 備份。全部取代時一起換；指定期間還原不動信用卡資料，關係所指的記帳若被換掉會自動變成「需要確認」。 |
| D-95 | 入口：明細頁頂端「匯入刷卡紀錄」「信用卡核對」兩個按鈕。不新增分頁。 |
| D-96 | 解析寧缺勿錯（驗收四輪後改為結構性做法，不再逐案補規則）。帳單：只讀「日期［日期］說明 單一台幣金額」這種嚴格版面；說明裡若還有其他數字、外幣代碼/符號/中文幣名（外幣金額緊接在台幣金額前除外）、卡號標示、單獨的正負號，或金額有分、緊貼字母或 $¥€:* 等符號，一律進「無法辨識」；含標題字樣但長得像明細的行、含日期或疑似日期的行、以數字結尾的行，也都進「無法辨識」，不默默丟掉；只讀到一個日期、日期在週期之後、或沒印年份推算後離週期超過兩個月的，保留但顯示警告。通知：只有「完整且乾淨」的消費通知（消費字樣緊接金額＋商店＋卡號末四碼或時間，且全文沒有回饋、優惠、驗證碼、退款、取消、失敗等字樣）才預設匯入；其餘看起來像消費的一律列為「需要你確認」、預設不勾；金額後面緊接優惠字樣（享、送、即可、以上、折…）時分不出是消費還是門檻，列為無法解析、請自行記帳；帳單/扣款/繳款通知一律不是消費。代價：若 Richart 真實通知不含卡號與時間，或固定附帶回饋字樣，每筆都要手動勾選。取得真實樣本後依樣本放寬（只改 notificationParser.ts）。 |

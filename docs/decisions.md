| D-89 | 核對引擎獨立於 UI（`src/card/reconcile.ts`），規則集中在 `RECONCILE_RULES`：同卡、金額相同、日期差 ≤3 天（只有入帳日時 ≤7 天）才是候選；唯一候選且（商店相近或日期差 ≤1 天）→ 自動核對；多個候選且無法以商店唯一區分 → 需要確認；同卡、日期 ≤3 天、商店相近但金額差 ≤10% → 需要確認（金額不一致）。 |

| D-91 | 記帳多的範圍：同卡、消費日期落在帳單週期內的支出。帳單週期未確認時不判定記帳多（只提示）。週期最後 5 天內的未配對記帳視為「可能下期列帳」，不算記帳多。使用者可標「等待下期帳單」。 |
| D-92 | 核對關係保存配對當下的金額／日期／卡片；記帳之後被修改或刪除，關係自動變成「需要確認（記帳已變更）」，不會顯示為已核對。核對永遠不修改記帳的消費日期；只有使用者按「改成帳單金額」才改金額。 |
| D-93 | 「已核對」標示只出現在已核對的信用卡交易旁；未核對不加任何警示（沒有帳單≠有問題）。 |
| D-94 | 信用卡資料（通知紀錄、匯入批次、帳單、明細、核對關係）納入 JSON 備份。全部取代時一起換；指定期間還原不動信用卡資料，關係所指的記帳若被換掉會自動變成「需要確認」。 |

## 資料模型補充

- 交易欄位完全照第 0 章 0.8。`occurredAt`、`createdAt`、`updatedAt` 存 ISO 8601（UTC），顯示與月份計算一律換算成 iPhone 本地時間。

## 資料安全

| # | 決策 |
|---|---|
| D-40 | 選好備份檔後有兩種還原：「全部取代」（用備份檔完全取代目前資料）或「只還原某段期間」（D-44）。兩種都會在還原前自動保留 1 份「還原前資料」，設定頁可退回（退回前也要確認）。 |
| D-44 | 指定期間還原 = 取代該期間：目前資料中起迄日期（含，本地時間）內的交易移除，換成備份中同期間的交易；期間外的交易、所有設定都不動（2026-10-10 User 確認 Q27–Q31）。 |
| D-45 | 期間用起、迄兩個日期選，預設為備份檔中最早與最晚的交易日期；確認畫面寫出「備份這段期間 N 筆，會取代目前同期間 M 筆」。 |
| D-46 | 備份期間內的交易用到、但目前沒有的分類或付款方式，會自動加回來（排在最後）；已存在的分類與付款方式維持現狀。同一個分類在備份與目前的收支類型不同時，不還原並提示。 |
| D-47 | 同一筆交易（同 id）在目前資料中被改到期間外的日期時，以備份版本為準，移回期間內；確認畫面會另外註明筆數。 |
| D-41 | （提醒條件已由 D-102 取代）備份提醒：距上次備份 >30 天且期間新增 ≥20 筆 → 首頁頂端顯示可關閉的一行提示；關閉後 7 天仍未備份再出現。設定頁持續顯示「上次備份：X 天前」。 |
| D-42 | CSV 欄位：日期、時間、類型、金額（一律正數）、分類、付款方式、商家、備註。UTF-8 加 BOM。（D-124 在最後加兩欄：帳戶、轉入帳戶） |

## 信用卡模組（通知匯入＋帳單核對，2026-10-11）

規格來源：「Money App｜信用卡自動記帳與銀行帳單核對模組」（User 提供）。User 回覆：iOS 27 捷徑有 App 通知觸發器可選 Richart Life（Q56=a，待實機確認內容）；信用卡模組完成後才一起上線（Q57=b）；樣本之後提供（Q58）；有多家銀行的卡（Q59=c）；不保存 PDF（Q60=a）；其餘「直接實作，有問題由 Claude 決定」。下列 D-80 起除註明者外皆為實作時決定。

| # | 決策 |
|---|---|

| D-81 | 通知 JSON 格式 v1：`schemaVersion, captureId, sourceApp, sourceType, title, subtitle, body, notificationTime, capturedAt`；欄位可為 null。一個檔可放一則或一個陣列。格式定義與範例見 `docs/shortcut-setup.md`。 |

| D-84 | 卡片對應：通知有末四碼就對末四碼；否則用「上次為 Richart Life 選的卡」；都沒有就請使用者在預覽選一次並記住。 |
| D-85 | 自動分類：先找同卡或任何過去記錄中商店名稱相近者的分類；再用內建關鍵字（便利商店、外送→餐飲；加油、交通→交通…）；都沒有用「其他」。 |
| D-86 | PDF 用 PDF.js（pdfjs-dist 5.7.284）在 iPhone 本機解析；worker 與 CJK cMap 隨 PWA 打包並預快取。密碼只存在記憶體、只用一次。掃描影像（無文字）明確告知不支援。 |
| D-87 | 帳單解析分兩層：PDF→文字行（通用）與「銀行格式轉接器」。目前只有通用轉接器（偵測日期＋金額行），沒有真實台新樣本前一律標「帳單解析待確認」，使用者在預覽可修改、刪除、補登明細，確認後才可標為已確認。 |
| D-88 | 同一份 PDF（雜湊值相同）不能重複匯入；同卡同帳單月份已有帳單時提示並讓使用者選擇取代或取消。 |
| D-89 | 核對引擎獨立於 UI（`src/card/reconcile.ts`），規則集中在 `RECONCILE_RULES`：同卡、金額相同、日期差 ≤3 天（只有入帳日時 ≤7 天）才是候選；唯一候選且（商店相近或日期差 ≤1 天）→ 自動核對；多個候選且無法以商店唯一區分 → 需要確認；同卡、日期 ≤3 天、商店相近但金額差 ≤10% → 需要確認（金額不一致）。 |
| D-90 | 一筆帳單明細最多對一筆記帳，一筆記帳最多被一筆明細使用（跨所有帳單）。退款、手續費、分期、調整、其他非一般消費的明細一律「需要確認」，不自動核對；繳款不參與核對，列在帳單其他資訊。 |
| D-91 | 記帳多的範圍：同卡、消費日期落在帳單週期內的支出。帳單週期未確認時不判定記帳多（只提示）。週期最後 5 天內的未配對記帳視為「可能下期列帳」，不算記帳多。使用者可標「等待下期帳單」。 |
| D-92 | 核對關係保存配對當下的金額／日期／卡片；記帳之後被修改或刪除，關係自動變成「需要確認（記帳已變更）」，不會顯示為已核對。核對永遠不修改記帳的消費日期；只有使用者按「改成帳單金額」才改金額。 |
| D-93 | 「已核對」標示只出現在已核對的信用卡交易旁；未核對不加任何警示（沒有帳單≠有問題）。 |

## 資料模型補充

- 交易欄位完全照第 0 章 0.8。`occurredAt`、`createdAt`、`updatedAt` 存 ISO 8601（UTC），顯示與月份計算一律換算成 iPhone 本地時間。
- Category 在第 0 章欄位之外多一個 `sortOrder`（整數），用來固定顯示順序；新增的分類排在同類型最後。
- PaymentMethod 同樣多一個 `sortOrder`。
- （D-117–D-124，資料庫版本 5）Transaction 新增選填 `toAccountId`（互轉的轉入帳戶）、`sourceAccountId`（用轉帳／行動支付付款時錢從哪個帳戶出）、`feeOf`（手續費所屬的互轉 id）；`type` 多了 `transfer`。PaymentMethod 新增選填 `balanceFrom`（起算時間，ISO）、`openingBalance`、`payFromId`。新資料表 `adjustments`（餘額調整：帳戶、時間、調整前、調整後、差額、原因）。升級時不改任何舊資料。
